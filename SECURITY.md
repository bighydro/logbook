# Security

This software stores a person's whole life. Treat every bug as if it were serious.

Report vulnerabilities privately to the address in the repository profile. You will get a reply within 48 hours. Fixes ship before disclosure.

Threat model (v0.1): the logbook lives on a machine the owner controls. The adversary is anyone who obtains the files. Tier 1 is plain; tiers 2 and 3 are encrypted at rest from v0.2 with a key that never leaves the owner's machine. There is no server and no account. Adapters are untrusted code: they run without network by default and can only append.

Reading never opens a connection. `day`, `days`, `show`, `trips`, `trip`, `rollup`, `derive`, `year`, `digest`, `stats`, `ledger`, `keepers`, `search`, `verify`, the pages `serve` renders and `mcp --inspect` read the record and the tables shipped in the package, nothing else; a socket is opened only behind a command that says so — `sync` for the live source it names, `transcribe --fetch-model` for a model this machine has not got, `serve` listening on 127.0.0.1 and refusing any other host — and never on an adapter's default path. This is a test, not a promise: `tests/test_no_network.py` replaces the socket, `urllib`, `http.client` and, where installed, the `httpx`, `requests` and `websockets` request paths with ones that record and refuse every connection (the `no_network` fixture of `tests/conftest.py`), runs each of those commands against the demo record and every page of `serve` through the site the server answers from, and fails if any of them so much as asked for one, whatever it printed or caught. The same run holds `verify` on `conformance/sample-logbook` to the head `conformance/README.md` documents. A change that needs a reader to fetch anything is wrong; a new reader goes into that test's list.
