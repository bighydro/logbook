# Audit — October 2026

Measured on 3 October 2026 against commit `4d70394` (`main` after #200, version 0.5.0). Every number below comes from a command in the appendix; re-run them on a later commit before quoting them.

## 1. Summary

1. The package is `logbook/` (there is no `src/` layout): 131 Python files, 57,227 lines, 20,331 of them in `logbook/adapters/`.
2. `logbook/cli.py` is 5,709 lines, imports 61 package modules at module level, and `import logbook.cli` loads 77 of the package's 131 modules before any command runs.
3. `logbook --help` lists 46 top-level commands in 119 lines.
4. 66 modules sit under `logbook/adapters/`; the `BUILT_IN` tuple names 58; `pyproject.toml` registers 25 entry points, every one a duplicate of a `BUILT_IN` name.
5. 31 profile strings appear in the package: 27 line profiles and 4 package manifests. 21 line profiles are read by a reader, rollup, derive or page; 6 are written and read by nothing but `show` or `search`; `commitment/v1` and `commitment-close/v1` are neither written nor read.
6. RFC number 0025 names two different documents; RFC 0028 is one file under two names; 22 of the 27 RFCs in `rfcs/` are not on the docs site, and the site build has 48 broken links.
7. The README names 17 commands and 14 profiles; all exist. 28 of the 46 top-level commands are not named in the README.
8. The suite collects 2,853 tests in 141 files (50,594 lines); 7 are `stress`, 7 `slow`; 21 Hypothesis properties; 587 `readouterr()` calls; 8 whole-output equality assertions; 22 monkeypatches of underscore-prefixed names.
9. No test loads a model: `judge`, `describe`, `transcribe` and `promises --judge` are tested through an injected `importer` and a `FakeEngine`.
10. The runtime dependency is `ijson` (5 adapter modules) plus `tzdata` on Windows; `encrypted` and `share` are the same extra; `judge` and `describe` install nothing off Apple silicon.

## 4. What disagrees with itself

- **Two adapter registries.** `BUILT_IN` (58) and the entry points (25) register the same modules by different names (`apple-books` vs `apple_books`); 33 adapters are in one and not the other; `docs/adapters/README.md` describes third-party adapters registering the entry point, which is the only purpose the group serves.
- **`screentime`** writes kind `app-use` with schema `event/v1`; every other writer of `event/v1` writes kind `event`. `rollup attention` selects by `screentime.KIND`, so the lines are read; `day.py`'s `event` selection does not see them.
- **RFC 0025** is two documents: `rfcs/0025-trip-bundle-v1.md` (`trip-bundle/v1`, `trip-share/v1`, `received/v1`; 119 lines, dated 2026-10-03) and `docs/rfcs/rfc-0025-shared-page-bundle.md` (`shared-page/v1`; 217 lines, dated 2026-10-02). `rfcs/README.md` links both under the same number.
- **RFC 0028** is one file with two names: `rfcs/0028-story-v1.md` and the symlink `docs/rfcs/0028-story.md`; `mkdocs.yml` names it "0028 story/v1 (draft, unfinished)".
- **RFC 0027** exists only under `docs/rfcs/`; the sequence in `rfcs/` skips it.
- **`rfcs/README.md`** calls `commitment/v1` a seed profile and links its RFC; the code has no writer and no reader.
- **`SPEC.md` §4** places `commitment/v1` and `commitment-close/v1` in the tier table beside profiles the code writes.
- **README vs code.** Every command the README names exists: 17 top-level names in backticks, 50 two-word forms (`export vault`, `backup restore`, `infer keepers`, `add story`, `rollup money`, …), all dispatched in `cli.py`. Every profile the README names (14) is written by the code. The README does not name 28 of the 46 top-level commands: `assets circle days describe digest import import-backup index infer keepers ledger migrate people person questions receive repair retract rollup search share show stats tasks transcribe trip trips verify year` (several appear in two-word forms or without the `logbook` prefix). The README's live-source table names 5 of the 9 live adapters; `adsb`, `ais` and `weather` appear in command examples, `apple-podcasts` nowhere.
- **The docs site** builds with 48 warnings, every one a link to a file outside `docs/`: 26 from `rfcs/README.md`, 15 from `index.md`, 6 from `CHANGELOG.md`, 1 from `CONTRIBUTING.md`. `mkdocs build --strict` fails; `.github/workflows/docs.yml` deploys without `--strict`.

## 5. Tests: what the suite guards and what it only pins

What it guards:

- The envelope and the chain: `conformance/sample-logbook` with `conformance/expected.json` is verified in CI by `logbook verify --expect`, and `tests/test_jcs.py` pins RFC 8785 hashing.
- Adapters against drift: 21 Hypothesis properties in 16 files generate exports and assert every yielded line validates; `test_fuzz_readers.py` carries 3 of the 7 `slow` marks.
- No network on the default path: `tests/test_no_network.py` and the socket guards in `conftest.py`, `test_describe.py`, `test_promise_judge.py`, `test_transcribe.py`, `test_ais.py`, `test_gcal.py`, `test_serve.py`, `test_mcp.py`.
- The CLI end to end: 26 files run `logbook` through `subprocess.run`.

What it only pins:

- Console text. 587 `readouterr()` calls and 862 substring assertions on captured output check wording, column layout and phrases from `cli.SKIP_PHRASES`. A rename of a command or a rewording of a line fails tests without any line of the record changing. Whole-output equality is rare (8 assertions), so the pinning is by phrase, not by screen.
- Private names. 22 `monkeypatch.setattr` calls target underscore-prefixed attributes (`_together`, `_finite`, …); those tests bind the suite to the current factoring of the module.
- The model commands. `test_promise_judge.py` (16 tests), `test_describe.py` (19) and `test_transcribe.py` (20) pass a fake `importer` or a `FakeEngine` into `judge.py`, `describe.py` and `transcribe.py`; no test imports `mlx_lm`, `mlx_vlm`, `mlx_whisper` or `faster_whisper`, and `tests/test_mcp.py` is the only `importorskip`. The suite proves the plumbing around a model, never a model's answer.
- Markers. `slow` tests run only with `LOGBOOK_SLOW=1` (CI: push to `main` and nightly, not pull requests); `stress` never runs in CI. A pull request therefore runs 2,839 of the 2,853 collected tests and skips 7; the one test that takes 56% of the wall clock, `test_demo_years.py::test_the_long_trips`, has no mark and runs on every pull request.

## 6. Dependencies

- One runtime dependency, `ijson`, carried by 5 of 66 adapter modules; the other 126 modules of the package need the standard library only. A core without adapters has no third-party dependency.
- Two extras are one: `encrypted` and `share` both declare `cryptography>=42` and resolve identically.
- Three extras are Apple-silicon-only in effect: `judge` and `describe` install nothing on any other platform and the commands exit 2 with an install line; `transcribe` falls back to `faster-whisper`, which pulls `torch` (45 packages).
- `mcp` pulls 32 packages (`pydantic`, `starlette`, `uvicorn`, `jsonschema`, …) for one command, `logbook mcp`.
- The dev group installs `pytest`, `pytest-xdist`, `pytest-cov`, `hypothesis`, `ruff`, `mypy`, `pre-commit`; `mkdocs-material` and `pymdown-extensions` are not in the lockfile and the docs workflow fetches them with `uvx`.

## 7. The three decisions

Recorded as the owner gave them on 3 October 2026.

**Decision 1 — Commands:** 46 top-level commands become 22. Every old name stays as a hidden alias that prints one line naming the new command. Help fits on one screen.

**Decision 2 — Profiles:** the profiles read by readers are frozen for v1.0 (expected 18); profiles written but never read are parked (expected 10): their adapters keep writing them, their schemas are marked "parked, may change", nothing is frozen about them. commitment/v1 and commitment-close/v1, neither written nor read, are deleted. trip/v1 is renamed journey/v1 with a reader-side alias for existing records. The freeze is specified in its own RFC.

**Decision 3 — Packaging:** one package, `openlogbook`, with three tiers inside it — core (format, record, verify, the frozen profiles' readers), contrib (adapters, exports, derived readers), labs (model-touching and experimental commands). Old import paths keep working through shims for one minor version. No split into two distributions before v1.0.

## 8. Order of work

1. **Hygiene first**, because every later step is measured against a baseline without duplicates: delete the 25 entry points or `BUILT_IN` (one registry); move the three regular files out of `docs/rfcs/` or the 22 missing RFCs into `mkdocs.yml`; renumber one of the two 0025s; make `mkdocs build --strict` pass and run it in CI; remove `commitment/v1` and `commitment-close/v1` from `SPEC.md` §4, `rfcs/README.md` and `docs/promises.md` and mark RFC 0007 withdrawn. No behaviour changes; no changelog line a user needs.
2. **One package, three tiers** (Decision 3), because the command and profile work must land in the tier it belongs to: `logbook/core`, `logbook/contrib`, `logbook/labs`, with shims at the old paths. The import graph in §2.2 is the checklist: `cli.py` must stop importing 61 modules at module level or every tier loads for every command.
3. **Commands** (Decision 1), because it depends on the tiers: 46 become 22, old names become hidden aliases, and the 862 substring assertions on console output in §2.7 tell which tests pin the old wording.
4. **Property tests** for the frozen readers, because the freeze needs a guard that does not depend on console phrases: one Hypothesis property per frozen profile asserting that any valid line is read without error and that `Day` is a function of the lines alone, alongside the 21 properties that already cover adapters.
5. **The freeze RFC** (Decision 2) last, because it names the 18 and the 10 from the tiers and the readers as they stand after steps 2–4, renames `trip/v1` to `journey/v1`, and is the one document the v1.0 tag points at.
