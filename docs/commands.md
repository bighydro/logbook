# The commands

`logbook` has 32 commands, grouped here by what you are doing. `logbook --help` is this list on one
screen; `logbook <command> --help` has a command's arguments. Everything that was a command of its
own before 0.6 still answers to its old name: it prints one line saying the new one and runs it (the
table at the end, generated from the code by `scripts/command_aliases.py`).

One writer at a time: a command that appends (`add`, `sync`, `import backup`, and every other through
`append`) holds `state/writer.lock` in the record folder for its whole run, a `sync`'s walk included.
A second writer says `another logbook command is writing to this record (sync immich, since
2026-09-10T06:00:00Z); waiting` and waits; with the global `--no-wait` it refuses and exits 2. A lock
whose process is gone is taken over with one line saying so. Readers (`show`, `day`, `verify`, every
reader) never take it. The lock is the courtesy between writers; what keeps the chain whole is that a
writer reads `logbook.json` again before every batch and writes nothing when the head has moved.

## Start

| Command | What it does |
|---|---|
| `init` | create a logbook (default `~/Logbook`) |
| `setup` | the guided first run, one question at a time, resumable; and the record's settings: `setup places`, `setup assets`, `setup questions`, `setup day_start` ([where your day begins](settings.md)), `setup phone` (whether your own phone writes through the Library behind Tailscale Serve, off by default, [from your phone](serve.md#from-your-phone)), `setup speakers` (what separates voices on this machine and the voiceprints it keeps; `--fetch-model` downloads its models, the one network event; `--rebuild` makes the voiceprint registry again from the record, [speakers](speakers.md#voiceprints)); `setup map PATH` names the offline OpenStreetMap file maps are drawn from, its header read first, `--off` to remove it ([the map](map.md)); `setup places review` names the places you return to from what the record already knows, offline, and with `--ask-photos` from what your photo libraries say about the photos already in it ([places](places.md)) |
| `doctor` | the check-up, one line per check, exit 1 on a fail, the crossing ceilings, the record's home (ADR 0022), the last scheduled run, the last restore test and the serve service among them, and lines dated outside their source's plausible range (`--implausible` lists them, [The doctor](doctor.md)); `--packet [--out FILE]` is a diagnostic to send a collaborator, with no line's content, no name, no home path and no value in it, and one probe of the dream endpoint when it is set ([Sending a diagnostic](doctor.md#sending-a-diagnostic)); `doctor sources` lists every adapter and, with `--gaps`, where each went quiet |

## Write

| Command | What it does |
|---|---|
| `add` | a sentence in your words, an export file, a folder of them, or `flight "LX 561 NCE ZRH …"`; `--trip ID "NAME"` names a journey; `add gift DAY NAME "WHAT" [--received]` what you gave someone, or were given: one `note/v1` line labelled `gift`, the person under `extra.recipient` or `extra.giver`; a name that is nobody, several people or you is refused in one sentence ([gifts](gifts.md)) |
| `import` | `import backup DIR` reads every phone source of an iOS backup; `import trip-bundle FOLDER` a trip another record exported; `import page FILE` a day someone shared; `import inbox` what is in `inbox/`; `import attachments` the attachment store |
| `sync` | pull new items from a live source (immich, dawarich, imessage, beeper, gcal, drive, gtasks, meet, gaudit, granola, mail, gmail, notion, telegram, github, ais, adsb, weather); `--all` for every configured one, immich last; beeper: `--networks` chooses the bridged networks; an interrupted immich walk resumes, `--restart` walks the library again; `sync mail` reads a mailbox over IMAP, read-only, resumed per folder from the last batch written (`LOGBOOK_IMAP_HOST`, `_USER`, `_PASSWORD`; `--since` searches from that day, `--restart` drops the marks); `sync notion` writes what happened to each Notion page on each day, one `event/v1` line per page, day and action, never the page's text, a database row with its database and the ids of the rows its relations link to (`LOGBOOK_NOTION_TOKEN`; `LOGBOOK_NOTION_ROOTS`, `LOGBOOK_NOTION_OWNER_ID`), and `--relations-backfill [--since DAY]` one line per row whose relations the record does not hold yet (`--dry-run` counts them); `sync telegram` writes what you sent your own bots from what the Bot API still holds, read-only, never confirming an update (`LOGBOOK_TELEGRAM_BOT_TOKENS`, `LOGBOOK_TELEGRAM_OWNER_ID`; [Your own agents](adapters/agents.md)); `sync github` writes a line per commit, issue or pull request created, closed or merged, review and comment, read-only, a watermark per repo (`LOGBOOK_GITHUB_TOKEN`, `LOGBOOK_GITHUB_REPOS`; your handles in `policy/owner.json`), and `add github-export DIR` an old project's commits and doc versions (a private repository's lines are tier 2, a clone's too unless `--public`); `sync gmail`, `sync gcal`, `sync drive`, `sync gtasks`, `sync meet` and `sync gaudit` read Gmail (the line `sync mail` writes), the calendars you own, Google Drive's activity with each file's folder path, Google Tasks, your Meet calls (and their transcripts, as Granola's are) and your own sign-ins from the Workspace's login audit log (never the address), read-only, with one Workspace service account, a scope per source (`LOGBOOK_DRIVE_SA_KEY`, `LOGBOOK_DRIVE_USER`; gcal reads its iCal feeds, `LOGBOOK_GCAL_URLS`, only without them; the tour's *Google, on one key*); `sync drive --videos` lists the family's video folder (`LOGBOOK_DRIVE_VIDEOS_FOLDER`) instead, one `video/v1` line per file from Drive's metadata, nothing downloaded ([Videos](adapters/videos.md)); `--install-schedule` runs `sync --scheduled` (`sync --all`, then `doctor`, the outcome to `state/last-run.json`, one message when something is wrong; a source's first scheduled run reads its last 14 days, never its whole history, [the schedule](schedule.md#a-sources-first-scheduled-run)) at 00:00, 12:00 and 18:00, and at 06:00 `sync --scheduled --close`, which closes the day (the dream's catch-up after the sync); `--system` for a machine nobody logs in to |
| `goal` | your goals, one `goal/v1` line each in your own words, tier 2 ([goals](goals.md)): `goal add TEXT --horizon life\|year\|quarter [--from DAY] [--until DAY] [--supersedes GOAL]` writes one (a goal reworded is a new goal that supersedes the old); `goal review GOAL advancing\|stalled\|done\|let-go\|superseded [--note TEXT] [--at DAY\|RFC3339] [--period day\|week\|month\|quarter\|year]` your verdict on it, on the day it is about (written in October about August, it is on the August Day); `goal list [--open] [--json]` every standing goal with its latest review; `goal import FILE [--horizon H] [--from DAY] [--review DISPOSITION [--at DAY] [--period P] [--note TEXT]] [--dry-run]` the first backfill, one goal per line of a text file (`text \| horizon \| from`), one verdict for all of them when given |
| `chapter` | a stretch of your life you name, one `chapter/v1` line, tier 2: `chapter open NAME [--from DAY] [--to DAY] [--rules TEXT]`, `chapter close [--to DAY]` (the open chapter written again with its last day), `chapter list [--json]`; chapters do not overlap, and the Day's header names the chapter a day is in ([goals](goals.md#chapters)) |
| `review` | one sitting for what the sources saw and the record has not placed: `review person` (= `people review`), `review org`, `review idea`, `review asset`, `review place` (= `setup places review`), each proposal numbered with its evidence or as a new one; `--accept N[,N]`, `--name N "…"`, `--reject N[,N]`, `--all-above SCORE`; nothing written unless told, nothing looked up; `review` alone lists every queue ([review](review.md)); `review speakers` the voices of your recordings not yet named, each answer one `resolution/v1` line per voice, `--unnamed N [--same-as M]`, `--consent N=yes\|no\|unknown`, `--play N`, `--named --recording ID\|--day DAY` to correct one ([speakers](speakers.md#who-they-are)); `review video` is a sixth queue, the scenes `videos infer` proposed a place or a date for, the surest first, each with the sentences, frames and speech it rests on and, for a proposed day, where the record had you and your assets: `--accept N[,N]` writes one `attribution/v1` line per scene (the video's own line is never touched), `--reject N[,N]` the scene's no, one `scene-review/v1` line that no other queue reads, and its own options, refused for every other kind, `--place N NAME` and `--date N WHEN` to confirm with your own, `--ask N[,N]` an open task to ask the family, `--asked`, `--answered`; `--top N` the first N scenes, as for a place ([Videos](adapters/videos.md)); `review goal` your open goals not yet reviewed this week, each answered `--say N advancing\|stalled\|done\|let-go\|superseded [--note N TEXT]`, the line `goal review … --period week` writes ([goals once a week](review.md#goals-once-a-week)); `review idea` lists, marked `[call]`, the ideas a call's synthesis proposed, nothing on the Ideas shelf until you accept one ([ideas from calls](review.md#ideas-from-calls)); `review with --journey ID\|--week YYYY-Www\|--from D1 --to D2` asks once who was with you over the stretch, the evidence in words, faces from your own camera only, answered `--accept N[,N] [--days D,D]` (the queue's numbers) or `--not NAME` ([who was there](who-was-there.md#the-review-with-queue)) |
| `status` | `status KIND ENTITY DISPOSITION [--reason "…"] [--at YYYY-MM-DD] [--portfolio "…"]`: what you decided about an org (`hold`, `add`, `sell`, `let-go`, `exited`, `passed`), an idea (`spark`, `exploring`, `build`, `built`, `killed`), a place (`let-go`) or an asset (`sold`, `let-go`), one `status/v1` line, tier 3 for an org and 2 for the rest, the reason on it, and for an idea, a place or an asset also as a tier-2 note (an org's reason stays on its tier-3 line); `--portfolio` names which portfolio holds an org, on that line (`""` clears it; an org's only); a place or asset it closes keeps its registry entry, closed with `until`; `status list KIND` ([the profiles](entities.md#statusv1)) |
| `star` | `star LINE [--note TEXT]` marks a line worth keeping: one `star/v1` line at the line's own time and tier, so it travels where the line does; a photo's star is a `memory` keeper, the Day's hero and the photo the press picks; starred again with another note, the new note supersedes ([the acts](acts.md)) |
| `unstar` | `unstar LINE` takes a star back: a retraction of the line's star, or of each `memory` keeper of a photo, at the star's tier; nothing is rewritten ([the acts](acts.md)) |
| `with` | `with DAY NAME [NAME…] [--at HH:MM]` says who was there when the record could not see: one `note/v1` line per person, `with <name>`, which `people` and the Day read as company; a name the record does not place is refused with the `people review` hint ([the acts](acts.md)); `with --from D1 --to D2 NAME` the same line on every day of a stretch of 60 days at most, each at that day's longest stay in its waking hours, `day_start` to midnight ([who was there](who-was-there.md)) |

## Read

| Command | What it does |
|---|---|
| `show` | one day's lines (default today); a page: `show person\|asset\|place\|org\|idea NAME`; a reader: `show year YYYY`, `show trip ID-OR-DAY`, `show trips`, `show days`, `show keepers`, `show stats`, `show orgs [--portfolio TEXT] [--money [--year YYYY]]` (the orgs you named under their status, the most recent touch first, the stale ones said, the passed with their reasons, the people with more than one org; only the orgs one portfolio holds with `--portfolio`; the ledger only with `--money`) ([orgs read back](entities.md#the-orgs-read-back)), `show ideas [--year YYYY]` (the ideas you named by stage, the most recent touch first, each with its reason, the people it was discussed with counted and named only on its page) ([ideas read back](entities.md#the-ideas-read-back)), `show plan [DAY] [--json] [--coverage]` (today's tasks, the sprint and the next trip, from the tier-1 lines `sync notion` wrote, each row with its Notion link, never its text; nothing written to Notion) ([the plan](plan.md)) |
| `day` | one day read back: the night, country, stays and moves with who and what, flights, health, whether every usual source is in, and whether you signed it; `day sign YYYY-MM-DD [--note TEXT] [--confirm ID,ID\|all\|none] [--at RFC3339] [--kept ID,ID] [--missed ID,ID] [--dropped ID,ID] [--carried ID,ID] [--accept N,N]` signs it, says what became of the commitments on it, lists the events the dream proposed and with `--accept` writes the ones you accept as `event/v1` lines ([the dream](dream.md#proposed-events)), with `--confirm none` confirms nothing and still signs, signed again keeps what you confirmed before (`--confirm all` the whole page), and with `--at` carries the moment you clicked, not the moment it ran ([the signed day](signed-day.md)), and never confirms the dream's draft line; with `--keep N,N [--mend N="…"] [--revisit N=YYYY-MM-DD]` it first keeps the draft's numbered sentences as notes, its links as entity lines and its photo as a star, with `--word WORD` the day in a word, and with `--done T,T --tomorrow T,T --let-go T,T` the plan's tasks answered as `task` notes, all checked before the first is written ([keep and sign](signed-day.md#keep-and-sign)); `day reflect YYYY-MM-DD [--text TEXT \| --audio FILE \| --mic SECONDS \| --from-wispr [SEQ]] [--at RFC3339] [--sign [--accept N,N\|none] [--keep N,N …]] [--dry-run]` closes it in your words: the reflection typed, heard on this machine, recorded on macOS, or the day's Wispr Flow dictation that begins with "reflect", written as one `note/v1` line, its commitments, delegations and dispositions proposed by rules, and with `--sign` the day signed with the ones you accept ([closing the day by voice](signed-day.md#closing-the-day-by-voice)); the days together 1, 2, 3, 5 and 10 years ago as `anniversaries`, off with `--no-anniversaries` |
| `digest` | one day in 25 lines at most, closing with one question |
| `search` | full-text search through the index: words, `"a phrase"`, `kar*` |
| `people` | everyone the record names, never the owner; `people --priority` ranks them by a plain score; `people NAME` is one person's page; `people gifts [NAME] [--json]` the gifts you gave and were given, in the day's order, or one person's ([gifts](gifts.md)); `people merge` the same person named twice; `people review` who the sources saw that the record has not placed, proposed against the people it names, accepted or rejected only when told, `--from-google` with your Google contacts as names for it, never lines; `people drift [--min-days N] [--quiet-days M] [--year YYYY] [--show]` who you used to see and have drifted from; `people nearby PLACE \| --journey ID \| --days FROM TO [--radius KM]` who has been seen where you are about to go ([people](people.md)); `people mail [--since DAY] [--until DAY] [--json]` which mail is a person's (someone the record names as a person sent it to you, or you sent it to one) and which is other mail (nobody named, a no-reply sender, an agent), counted over the window, the last 30 days by default, never an address or a name in the terminal, `--json` with person ids and never an address; the rule the crossing sends mail by ([people's mail](mail-people.md)); `people ingest NAME --window FROM TO` and `people ask NAME QUESTION [--show-prompt]`, the relationship reader, experimental: the model of `LOGBOOK_DREAM_ENDPOINT` answers from the person's lines, and the days you spent together (their dates and the places' names, never coordinates), at or under the `relationship` entry's `max_tier`, signed days only unless it says `include_unsigned`, every claim citing them or listed as unsupported, nothing written ([the relationship reader](relationship.md)); `people not-with NAME --from D1 --to D2`, `people lives-with NAME --from D [--until D]` and `people lives-in NAME CITY` your word on who was there, one note each, and `people city CITY [--trip ID]` your people in a city, seen or not yet on a journey (`--journey` there is its old name until the release after 1.0) ([who was there](who-was-there.md)) |
| `rollup` | the record per year: countries, flights, nights, places, people, listen, attention, money; per month or week: health, attention; `rollup ledger` the transactions in context |
| `serve` | the record in a browser, from this machine only (`/today` is today's Day), answered from pages built at the 06:00 close and after every act ([built ahead](serve.md#built-ahead)); `--build` builds what changed since the last build now (`--full` every page), `--live` renders every page as it is asked for, `--limit SECONDS` stops a page read longer ([never hangs](serve.md#never-hangs)); `--install-service [--system]` keeps it running by launchd or systemd, `--status` says whether it answers; `serve mcp` serves it to an MCP host |

## Derive

| Command | What it does |
|---|---|
| `derive` | `derive stays` reads the record into stays and moves, appending nothing; `derive flights` and `derive keepers` infer lines; `derive transcripts voice-memos` and `derive descriptions keepers` run a local model, nothing leaving the machine; `derive transcripts` separates the voices too when the `speakers` extra and its models are here (`--no-speakers` turns it off), and `derive speakers` hears again the transcripts heard before, each into a line that supersedes the old ([speakers](speakers.md)) |
| `promises` | what you promised and what you were asked, from mail, messages, transcripts and notes, by rules, as proposals, in two sections with the line id a signed day confirms; `promises done ID` closes one; `promises tasks` the tasks, each as it stands |
| `dream` | `dream day YYYY-MM-DD [--dry-run] [--show-prompt]`: a model reads the day under the `dream` entry of `policy/crossing.json` and writes one `draft/v1` line, the day in a paragraph, the threads it moved, two questions, the people and promises it proposes, every sentence with the lines it came from or marked unsupported, and the events it thinks the day held, kept in the draft until you accept one; a proposal, shown on the Day above your note, never a fact; `dream journey ID` drafts a journey once it has come home (`show trips` and `show trip` carry it), and `dream week [DAY\|YYYY-Www]` an ISO week once its Sunday is over, from its seven days and their drafts, every figure the code's (the Day of its Sunday carries it; [journeys and weeks](dream.md#journeys-and-weeks)); `dream --catch-up [--days N] [--since DAY]` dreams each of the last N days that has no draft or whose lines changed, one line per day, then each week whose seven days are among them, then synthesizes the calls of the last 7 days that have none (from `DAY` on with `--since`), naming the older ones in one line, never sending them, then each journey that came home on one of the days, then the month whose last day is among them and each chapter that closed on one ([the dream](dream.md)); `dream month [YYYY-MM]` drafts a month once it is over, told from the days you signed, the people by name only and never with a count ([months](dream.md#months)), and `dream chapter [ID]` a chapter from the month and week drafts it spans ([chapters](dream.md#chapters)), each with `--json` |
| `dream person` | `dream person NAME [--window FROM TO] [--dry-run] [--show-prompt]`: a model reads what passed between you and one person (their authorized input set, RFC 0036 amendment 1) under the `relationship` entry of `policy/crossing.json`, never the `dream` entry, and writes one `draft/v1` line of unit `person`, every sentence citing their lines or marked unsupported; default window the 90 days that end today ([the relationship reader](relationship.md#dream-person)) |
| `videos` | the family's videos, which `sync drive --videos` names from Drive's metadata: `videos fetch [--limit N] [--again] [--cache-gb N]` downloads the next files nobody has inferred (with `--again`, the inferred ones too) into a bounded cache under `state/videos/` (8 GB unless you say), one at a time, each verified against Drive's md5, a dropped connection resumed; a file bigger than the cap is refused and said so; `--models` fetches the speech and vision models once; the only command of the videos that uses the network ([Videos](adapters/videos.md)) |
| `transcript` | `transcript synthesize ID\|--day YYYY-MM-DD [--dry-run] [--show-prompt] [--again]`: a model reads one call under the same `dream` entry and writes one `draft/v1` line about it (unit `event`): the actions proposed on top, with assignee and due hint, the topics consolidated across the call, the decisions, the open threads and a short personal part, every item with the utterances it rests on or marked unsupported; a transcript above the entry's `max_tier` stays home; shown collapsed under the transcript's row on the Day; `dream --catch-up` synthesizes those of the last 7 days that have none ([the synthesis](transcript-synthesis.md)); it may propose up to three ideas the call put forward, new or refining one you named, which wait in `review idea` ([ideas from calls](review.md#ideas-from-calls)) |

now `logbook Y Z` ``, and runs the new command with the same arguments and exit status, printing the
same thing. A script or an alias in your shell keeps working; change it when you like. The table is
written by `scripts/command_aliases.py` from `logbook/commands/aliases.py`, and a test holds the two
together.
