### Added
- `logbook export vault <folder> [--since YYYY-MM-DD] [--until YYYY-MM-DD] [--tier 1|1,2]` (`logbook/vault.py`, `docs/vault.md`): the record as a folder of plain Markdown an Obsidian or Logseq user opens as a vault — one page per day (the Day with YAML front matter: date, weekday, country, the nights either side, places, people, trip), one per named place in `places.json`, one per person confirmed present, one per trip, one per year and a root page, every page linked to the others with wikilinks, so the graph view shows the record's shape: home at the centre, days hanging off their places and people, trips as short chains, a year gathering all of it. Tier-gated exactly like a crossing (ADR 0016): a line is in the vault when its tier is in `--tier` and shows only as a count when it is not (`held back: 1 note`), so the default, tier 1, is the shape of every day with no text of any note, message, transcript or mail, and a person a tier-2 note names is not on the page until tier 2 crosses; the ceiling is the `vault` entry of `policy/crossing.json` (`policy.vault_ceiling`), tier 1 when the file does not name it; tier 3 is refused. Every run appends one `crossing/v1` line (RFC 0011) with destination `vault`, the window, the counts, the ceiling and the digest of the folder as written (one `<sha256>  <path>` line per file, hashed), so the record shows it left. Every page is a function of the record's lines and settings alone, so re-running rewrites only the files whose content changed and deletes nothing. Read a calendar year at a time, as `logbook year` reads it.
