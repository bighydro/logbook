### Housekeeping
- Property tests of the format (`tests/properties/`, the October 2026 audit): what SPEC.md guarantees, stated for any input and searched for a counterexample by Hypothesis — canonicalisation (§3, RFC 8785: idempotent, key order and stored whitespace aside, injective on values, `1` and `1.0` one number), the hash chain (§1, §3, §6: any sequence verifies, an append changes only the head, any byte flip of any line is rejected naming the line, a truncation reports the last good head), tiers (§4, ADR 0016: an export at tier t is exactly the lines at or below it, tier 1 carries no profile of tier 2 or 3 as SPEC.md's own table lists them, export then import is idempotent on the head), time (§2, §3.2: the day of a line is the local date in the record's zone, midnight turns the day, a DST transition leaves no instant without a day or with two, a duration is the real seconds elapsed), identity (RFC 0006: every spelling of a number or an address is one ref and one person, two identifiers never collide) and the attachment store (§1.1: store then load is the same bytes under their SHA-256, storing twice does not duplicate). The suite's Hypothesis profile is deterministic. The example tests these properties make redundant are gone. One property is marked `xfail(strict=True)`: a month file cut inside a line makes `verify` report seq 0 and GENESIS, not the head of the lines before the cut.
