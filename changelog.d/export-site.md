### Added
- `logbook export site <folder> [--tier 1|1,2]` (`logbook/site.py`, `docs/site.md`): the readers as a folder of static HTML — a Year page per year (the page `logbook year --html` writes), every Trip page (`logbook trip --html`, the map inside), a Days index per year (`serve`'s `/days` table, one row per day the record covers, each an anchor), the places (`/places`), the people (an index by days together, and a page per person with the years together and the trips) and a root page — written as plain files with relative links, one inline stylesheet each, no script, no image, nothing fetched, so the folder reads the same from a file manager, under any prefix on any web server, or in twenty years. `serve` written down: `serve.Site` takes `tiers`, `href`, `nav` and `footer` and renders a static page through them, `year.html` and `trip_page.html` take `nav` and `links`, and the rendering is the same either way. Tier-gated exactly like the vault (ADR 0016): the day, days, year and trip readers read the record through `reading.read(..., tiers)`, so a line whose tier is not in `--tier` is in no page, no stay, no night, no companion and no count; the resolution lines (the name overlay) are read whole, as the vault reads them, so a tier-1 site names whoever a tier-1 line confirms present; the ceiling is the `site` entry of `policy/crossing.json` (`policy.site_ceiling`), tier 1 when the file does not name it; tier 3 is refused. Every run appends one `crossing/v1` line (RFC 0011) with destination `site`, the window, the counts, the ceiling and the digest of the folder as written; re-running rewrites only the files whose content changed and deletes nothing.
- The demo persona's forty years, browsable without installing anything: the docs workflow (`.github/workflows/docs.yml`) now runs on every push to `main`, generates `logbook demo --years 40 --seed 1`, exports it with `export site` at tier 1 into `docs/ines/` and publishes it with the docs at `/ines/` on GitHub Pages — the same `gh-pages` branch, the same deploy. Before the build, `scripts/check_synthetic.py` fails the workflow if any page carries an identifier outside CONTRIBUTING.md's synthetic allowlist (an email at a domain other than `example.org`, a phone number outside `07700 900xxx` and `+47 9000 000x`, a nine-digit number in an assigned MMSI range, a URL of any kind) or anything the owner's `pii-patterns` file names, printing `file:line` and a count and never the text: the scrub rule, applied to the rendering.
