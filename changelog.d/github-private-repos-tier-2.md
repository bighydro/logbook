### Changed

- `sync github` and `add github-export`: a line from a private repository is tier 2, with the reason on the line (`extra.tier_reason`: `private repository`), so an issue's text, a review and other people's comments in a private repository no longer go wherever tier 1 crosses by default; a public repository's lines stay tier 1. The live sync reads each repository's own `private` and `visibility` from the answer it already asks for (`GET /repos/{repo}`, or `GET /user/repos` with `--all`): public only when the API says so, so an internal repository is private too. The account export's mark per repository is used where it exists; a clone says nothing of its visibility, so its lines, and those of a repository the export does not mark, are tier 2 (`repository visibility not known`) unless you pass `add github-export DIR --public` for that run, which never overrides a repository the export marks private. A visibility that changes applies to the lines written from then on; a line already in the record is never rewritten, and the same commit or issue read again at the other tier is the line already there, never a second one.
