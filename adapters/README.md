# Adapters

One adapter per source. A module with three names: `NAME` (the `source` it writes), `sniff(path) -> bool` ("is this file mine?", cheap, never raises) and `run(input_path, since) -> iterator[dict]` where each dict has the keys `at, end, tz, source, kind, tier, payload` (see SPEC §2) — everything except the chain fields, which the logbook adds on append. Give every line a stable `payload.raw_id`; `logbook add` skips lines whose `(source, raw_id)` are already in the log, so re-adding an export appends nothing.

Adapters built by the project ship inside the package under `logbook/adapters/` (ADR 0012); the first are `dawarich`, `google-takeout-location` (Google Takeout's Records.json and the on-device Timeline.json), `google-takeout-photos` (the Takeout `Google Photos/` folder → one `photo/v1` line per media file from its JSON sidecar, RFC 0002; the pixels are hashed, never copied; the `logbook/adapters/takeout/` package has `calendar` beside them and will gain activity) and `google-takeout-keep` (the Takeout `Keep/` folder → one `note/v1` line per note, RFC 0010: `raw_id` `keep:<created usec>@<modified_at>` so an edit is a new line and a re-import nothing, labels, pinned/archived/trashed/colour under `extra`, list notes as `[x]` lines, attachments by digest from the file beside the note and stored only with `--attachments`) and `google-takeout-tasks` (the Takeout `Tasks/Tasks.json` → one `task/v1` line per task, RFC 0016: `raw_id` `<task id>@<updated>` so a ticked task is a new line, `status` open/done, `due` as a day, `completed_at`, `list`, `notes`, `parent` for subtasks) and `google-takeout-chrome` (the Takeout `Chrome/` folder: `History.json` → one `browse/v1` `visit` per entry, `Bookmarks.html` → one `bookmark` per link with its folder path, RFC 0017; `raw_id` from the instant and the url's digest, never the file) and `safari` (Safari's `History.db` from an iPhone backup — `import-backup` copies it out and runs this — or the Mac's own → one `browse/v1` `visit` per row, the columns discovered by PRAGMA so an older or newer Safari still reads; the same visit from the phone and the Mac dedupes) and `google-takeout-youtube` (the Takeout `YouTube and YouTube Music/history/` JSON → one `watch/v1` line per video watched and per search, RFC 0018: title, channel, url, video id, the product as the service; ads and other activities skipped and counted; streamed with ijson). Not an adapter but of the same family: `logbook places import-takeout` reads Takeout's `Maps (your places)/` GeoJSON and `Saved/` CSVs and proposes entries for `places.json`, written only with `--write`. `shazam` (the app's `shazamlibrary.csv` → one `listen/v1` `track` per identified song, RFC 0019, the zoneless tag time read in the record's zone) and `apple-podcasts` (Apple Podcasts' `MTLibrary.sqlite`, a copy through `add` or the Mac's own through `logbook sync apple-podcasts` → one `listen/v1` `episode` per played episode, `raw_id` the episode uuid with its last-played time so a replay is a new line; the columns discovered by PRAGMA, so a store with more or fewer still reads) and `pocket` (a Pocket CSV export → one `browse/v1` `save` per saved page with its tags and read state, RFC 0017: not a note, since a saved page is not the owner's words) and `ios-contacts` (an iPhone's AddressBook.sqlitedb → one `resolution/v1` line per phone number and email address, minting the record's person and company ids — how a record gets its people, ADR 0013.2) and `whatsapp` (an iPhone's ChatStorage.sqlite → one `message/v1` line per message, RFC 0008; media by digest only until the §1.1 store exists) and `imessage` (an iPhone's sms.db from a backup, or live, the Mac's own chat.db through `logbook sync imessage` — one `message/v1` line per message either way, with the same `raw_id`, so the two dedupe each other; media by digest only) and `whatsapp-contacts` (an iPhone's WhatsApp ContactsV2.sqlite → one `resolution/v1` alias line per contact with a linked-device id, RFC 0006 `alias_of`: the `@lid` a group message carries paired with the phone number the address book resolves; nothing is minted) and `ios-notes` (an iPhone's Apple Notes NoteStore.sqlite → one `note/v1` line per note, RFC 0010; the body decoded from the gzip+protobuf archive with a stdlib-only walker) and `ios-calendar` (an iPhone's Calendar.sqlitedb → one `event/v1` line per stored entry, RFC 0009; rules as RRULE text, occurrences never expanded) and `ios-calls` (an iPhone's CallHistory.storedata, which only an encrypted backup carries → one `call/v1` line per call, RFC 0012: direction, answered, duration, the other end as a source-native phone/email/handle ref, never resolved, the service as the phone names it) and `apple-health` (an iPhone's `healthdb_secure.sqlite`, which only an encrypted backup carries → `health-sample/v1`, RFC 0014: steps, distance, energy and flights in 15-minute buckets per device, heart rate capped at one reading a minute, resting heart rate, HRV and weight as readings, sleep stages and workouts as spans; `healthdb.sqlite` beside the store names the sources) and `ics` (any iCalendar file, RFC 5545 — a Google Calendar or Takeout `Calendar/` export, an Apple Calendar export, a saved feed — or a folder of them → one `event/v1` line per VEVENT with the same shape as `ios-calendar`; a small tolerant stdlib parser, occurrences never expanded; or live, Google Calendar's private iCal feeds through `logbook sync gcal`, read by the same reader so a feed and an export of one calendar dedupe each other (ADR 0017)) and `ios-wallet` (an iPhone's Apple Wallet passes — the unpacked `.pkpass` folders a backup keeps under `Library/Passes/Cards/`, which `import-backup` copies out, or any `.pkpass` zip → one `flight/v1` line per leg of an air boarding pass, RFC 0013, evidence `tracked`, read from the airline's IATA BCBP barcode, the year from the pass's own dates and never guessed; one `event/v1` line per event ticket and per bus, boat or train boarding pass, RFC 0009, the issuer as the calendar, the front fields under `extra` minus names and credentials; store cards, coupons and generic passes skipped and counted; the PNR, the passenger's name and the barcode never kept; `logbook add wallet <folder|pass.pkpass>`) and `flighty` (a Flighty CSV export → one `flight/v1` line per flight, RFC 0013, evidence `tracked`: carrier spelled as IATA, the airports' wall-clock times converted to UTC through the shipped airports table, the PNR never kept; `logbook add flights <export.csv>`; a flight the owner already declared or the record already inferred is superseded by the merged line, never duplicated) and `transcript` (the universal transcript file adapter, RFC 0004 `transcript/v1`: JSON already in transcript/v1 shape — the interchange format for any tool — WebVTT, SRT, Markdown and plain text with `Speaker: text` lines → one line per file, the file's own bytes as the SPEC §1.1 attachment, `raw_id` `<source>:<sha256>`, tier 3 by default; `logbook add transcript <file|folder> --source <name>`) with `granola` as its live sibling (`logbook sync granola`: one transcript/v1 line per recording through the same mapping, `raw_id` `granola:<note id>`, plus the AI summary as a derived `note/v1` line); `ais` and `adsb` (ADR 0018: the positions of the owner's own vessels and aircraft, registered in `assets.json`, as location/v1 lines with `subject` set; `ais` reads a saved aisstream.io stream and `logbook sync ais` listens to its websocket for the registered MMSIs, `raw_id` `aisstream:<mmsi>:<unix seconds>`; `adsb` reads a saved OpenSky `states/all` response and `logbook sync adsb` polls it for the registered icao24 addresses, `raw_id` `opensky:<icao24>:<time_position>`) and `mail` (an mbox mailbox — Google Takeout's `Mail/` export, or any mbox file or folder of them → one `mail/v1` line per message, RFC 0015, streamed one message at a time: `raw_id` the `Message-ID` (`<account>:` first when `--account` names the mailbox, so a later live IMAP adapter dedupes against the export, ADR 0017), the thread root, sender and recipients as `{email, name}` refs never resolved, subject, date with its offset, Gmail labels, the body as text (HTML stripped without a library), size, attachments by digest and — only with `--attachments` — in the §1.1 store; `direction` from `owner_emails` in `logbook.json`; `--only-labels`/`--skip-labels`/`--since`; a message without a `Message-ID` keyed by its digest, never skipped). Third-party adapters are separate packages registering the `logbook.adapters` entry point. `logbook add <file-or-folder>` tries every registered adapter's `sniff` and runs the first match.

Rules: pure by default (no network), never write to the source, never invent `tier` lower than the source deserves, fixture-tested with **synthetic** data only. Backfill and live share one mapping (ADR 0017): where a source has both an export and an API, one function maps it and both `add` and `sync` call it, so a backfilled line and the same line pulled live have one `raw_id` and dedupe to one line.

Planned first (ADR 0008): `google-takeout`, `apple-health` (done), then `email` — the last now `mail`, file mode; its live IMAP mode is the next step under ADR 0017.
