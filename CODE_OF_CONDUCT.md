# Code of conduct

This project is a small crew building a tool that holds people's whole lives. The way we treat each other should match the care the tool asks of its owner.

## Our standard

Be kind, be precise, argue about the work. In issues, pull requests, discussions, commit messages, the docs and anywhere else this project is represented:

- Assume good faith and competence. Ask before concluding.
- Critique the change, never the person. Say what is wrong, why, and what would be right.
- Take correction gracefully. Being wrong in public is how a spec gets better.
- Respect people's time: one issue per pull request, a reproduction with a bug, a reason with a decision.
- Respect people's privacy more than anything. Nobody's real data, name, number or address enters an issue, a fixture or a screenshot. This includes your own, and it includes public figures.

The following are not acceptable, whatever the provocation: harassment or intimidation in any form; insults or demeaning remarks, including about someone's background, identity, body or ability; sexualised language or attention; publishing someone's private information; sustained disruption of a discussion; and retaliation against anyone who reports a problem.

## Scope

This code applies within the project's spaces and whenever someone is representing the project in public. It applies to the captain as much as to a first-time contributor.

## Reporting

Report a problem privately to the address in the repository profile. The captain reads every report, replies within a week, keeps the reporter's identity confidential and acts on it: a private word, a public correction, a temporary or permanent ban from the project's spaces, in proportion to the harm. A report about the captain goes to GitHub's own conduct process instead.
